क्रिएटर के स्वामित्व वाली रिलीज़ प्रणाली, XRP लेज़र पर। कार्य जारी करें, सीधे बेचें, संग्राहकों को लाभ प्रदान करें, राजस्व का प्रबंधन करें - ये सभी स्थायी ऑन-चेन प्रमाण द्वारा समर्थित हैं।

> **टेस्टनेट-प्रथम रिलीज़।** यह रिलीज़ लाइन एक टेस्टनेट उत्पाद है। इंजन आर्किटेक्चर टेस्टनेट और मेननेट दोनों का समर्थन करता है, लेकिन सभी ट्रस्ट प्रूफ केवल टेस्टनेट पर मान्य किए गए हैं। मेननेट एक सुरक्षित, जानबूझकर प्रचार है - डिफ़ॉल्ट नहीं।

## इसे उपयोग करने के दो तरीके

### डेस्कटॉप ऐप (क्रिएटर्स के लिए अनुशंसित)

[GitHub रिलीज़](https://github.com/mcp-tool-shop-org/xrpl-creator-capsule/releases/latest) से विंडोज इंस्टॉलर डाउनलोड करें और [शुरुआती गाइड](https://mcp-tool-shop-org.github.io/xrpl-creator-capsule/handbook/beginners/) का पालन करें।

**स्टूडियो मोड** आपको एक निर्देशित 6-चरणीय प्रक्रिया के माध्यम से मार्गदर्शन करता है:

1. अपनी रिलीज़ का वर्णन करें (शीर्षक, कलाकार, संस्करण आकार, फ़ाइलें)
2. संग्राहकों को लाभ निर्धारित करें (अतिरिक्त ट्रैक, स्टेम, उच्च-रिज़ॉल्यूशन कला)
3. नियमों और सुरक्षा की समीक्षा करें
4. XRPL टेस्टनेट पर प्रकाशित करें
5. संग्राहक पहुंच का परीक्षण करें
6. एक रिकवरी बंडल उत्पन्न करें

[Node.js 22+](https://nodejs.org/) की आवश्यकता है (भविष्य की रिलीज़ में बंडल किया गया रनटाइम)।

### सीएलआई (डेवलपर्स और इंटीग्रेटर्स के लिए)

```bash
git clone https://github.com/mcp-tool-shop-org/xrpl-creator-capsule.git
cd xrpl-creator-capsule
npm install
bash verify.sh    # full test suite (700+ tests), zero network calls
```

पूर्ण रिलीज़ जीवनचक्र को कवर करने वाले 15 कमांड:

| कमांड | उद्देश्य |
|---------|---------|
| `init-wallets` | जारीकर्ता + ऑपरेटर वॉलेट जोड़ी उत्पन्न करें और निधि दें |
| `configure-minter` | ऑपरेटर को जारीकर्ता खाते पर अधिकृत मिंटर के रूप में सेट करें |
| `create-release` | एक मैनिफ़ेस्ट इनपुट फ़ाइल से एक रिलीज़ बनाएं |
| `validate` | स्कीमा के विरुद्ध एक रिलीज़ मैनिफ़ेस्ट को मान्य करें |
| `resolve` | जांचें कि क्या मैनिफ़ेस्ट पॉइंटर संरचनात्मक रूप से मान्य हैं |
| `mint-release` | एनएफटी संस्करणों को मिंट करें और जारी करने की रसीद उत्सर्जित करें |
| `verify-release` | चेन स्थिति के विरुद्ध मैनिफ़ेस्ट + रसीद का मिलान करें |
| `create-access-policy` | मैनिफ़ेस्ट + रसीद से एक एक्सेस नीति उत्पन्न करें |
| `grant-access` | एक्सेस अनुरोध का मूल्यांकन करें और अनुदान रसीद उत्सर्जित करें |
| `recover-release` | कलाकृतियों + चेन स्थिति से एक रिलीज़ को पुनर्निर्माण करें |
| `create-governance-policy` | एक रिलीज़ ट्रेजरी के लिए एक शासन नीति बनाएं |
| `propose-payout` | एक शासन नीति के विरुद्ध एक भुगतान प्रस्ताव बनाएं |
| `decide-payout` | अनुमोदन एकत्र करें और एक निर्णय रसीद उत्सर्जित करें |
| `execute-payout` | भुगतान निष्पादन रिकॉर्ड करें और हैश श्रृंखला को सत्यापित करें |
| `verify-payout` | सभी 4 शासन कलाकृतियों और उनके संबंधों को सत्यापित करें |

## यह क्या साबित करता है

XRPL क्रिएटर कैप्सूल, XRP लेज़र को स्वामित्व, भुगतान, एक्सेस और उत्तरजीविता के लिए एक स्थायी नियंत्रण तल के रूप में मानता है। यह एक बाज़ार नहीं है - यह वह बुनियादी ढांचा है जो बाज़ारों को वैकल्पिक बनाता है।

| चरण | यह क्या साबित करता है |
|-------|---------------|
| ए - क्रिएटर इंटेंट | मैनिफ़ेस्ट पहचान नियतात्मक और छेड़छाड़-रोधी है |
| बी - मिंट ट्रुथ | XRPL पर एनएफटी मैनिफ़ेस्ट से बिल्कुल मेल खाते हैं (लाइव टेस्टनेट प्रमाण) |
| सी - एक्सेस ट्रुथ | स्वामित्व वास्तविक ऑफ़-चेन एक्सेस को अनलॉक करता है |
| डी - गवर्नेंस ट्रुथ | ऑडिट योग्य अनुमोदन श्रृंखला के माध्यम से राजस्व का प्रबंधन किया जाता है |
| ई - स्थायित्व सत्य | रिलीज़ फ्रंटएंड की मृत्यु से बच जाती है (डेथ ड्रिल पास) |
| डेस्कटॉप रनटाइम ट्रस्ट | मोड स्विच, पुनरारंभ, रुकावट, समय समाप्त, समय |

वर्तमान में सूट इंजन पैकेजों, सीएलआई और डेस्कटॉप ऐप पर **700+ परीक्षण** चलाता है - `bash verify.sh` यह सब चलाता है और लाइव गिनती प्रिंट करता है, जिसमें शून्य नेटवर्क कॉल होते हैं। (सूट बढ़ने के साथ सटीक संख्या बदलती रहती है; कमांड सत्य का स्रोत है।)

## आर्किटेक्चर

```
app/              Desktop app (Tauri v2 + React)
  src/            Studio Mode + Advanced Mode UI
  src-tauri/      Rust backend (file I/O, bridge dispatch)
  bridge-worker   Engine bridge (stdin/stdout JSON-RPC)
packages/
  core/           Canonical contracts, schemas, validation, hashing
  xrpl/           XRPL client (connect, mint, verify, holder checks)
  storage/        Content store + delivery provider interfaces
  xaman/          Wallet-mediated signing via Xaman
  cli/            15 CLI commands
artifacts/        Live Testnet proof artifacts
site/             Handbook (Astro Starlight)
```

5 इंजन पैकेजों + डेस्कटॉप ऐप के साथ मोनोरेपो। टाइपस्क्रिप्ट, विटेस्ट, टाउरी v2, नोड 22+।

## नेटवर्क मुद्रा

सिस्टम में पूर्ण नेटवर्क जागरूकता है - टेस्टनेट और मेननेट अलग-अलग, कॉन्फ़िगर करने योग्य लक्ष्य हैं।

| | टेस्टनेट | मेननेट |
|-|---------|---------|
| **Default** | हाँ | No |
| **Trust-proven** | हाँ (लाइव प्रमाण, पूर्ण सूट) | अभी तक नहीं |
| **CLI guard** | किसी की आवश्यकता नहीं है | `--network mainnet --allow-mainnet-write` |
| **Desktop app** | स्टूडियो मोड डिफ़ॉल्ट | डेस्कटॉप ऐप में उजागर नहीं किया गया |

**इस रिलीज़ को टेस्टनेट पूर्वावलोकन के रूप में मानें।** आर्किटेक्चर केवल टेस्टनेट नहीं है, लेकिन ट्रस्ट प्रूफ टेस्टनेट-सिद्ध है। मेननेट तत्परता के लिए लाइव ज़मान साइनिंग और जानबूझकर प्रचार की आवश्यकता होती है - यह कोई फ़्लैग फ्लिप नहीं है।

## ट्रस्ट मॉडल

**यह सिस्टम क्या छूता है:**
- स्थानीय JSON फाइलें (मैनिफेस्ट, रसीदें, नीतियां, बंडल)
- XRPL वाया वेबसॉकेट (`wss://`) मिंटिंग, सत्यापन और धारक जांच के लिए
- वॉलेट सीड वाक्यांश स्थानीय `wallets.json` में संग्रहीत हैं (गिट द्वारा अनदेखा किया गया, कभी भी कमिट नहीं किया गया)

**यह सिस्टम क्या नहीं छूता है:**
- XRPL नोड्स से परे कोई बाहरी एपीआई नहीं
- कोई डेटाबेस, क्लाउड स्टोरेज या तृतीय-पक्ष सेवाएं नहीं
- कोई उपयोगकर्ता विश्लेषण, ट्रैकिंग या टेलीमेट्री नहीं

**सुरक्षा सीमाएँ:**
- मेननेट लेखन के लिए स्पष्ट `--network mainnet --allow-mainnet-write` की आवश्यकता होती है
- वॉलेट क्रेडेंशियल स्थानीय रूप से रहते हैं - केवल लेनदेन हस्ताक्षर के लिए XRPL पर प्रेषित किए जाते हैं
- सभी हैश नियतात्मक `sortKeysDeep()` विहितकरण पर SHA-256 का उपयोग करते हैं
- प्रत्येक कलाकृति स्वतंत्र रूप से लेज़र के विरुद्ध सत्यापित की जा सकती है
- `xrpl` संस्करण 4.2.5 पर पिन किया गया (एनपीएम आपूर्ति श्रृंखला सलाहकार के बाद)

## ज्ञात सीमाएँ

- डेस्कटॉप ऐप के लिए **Node.js आवश्यक** है (बंडल रनटाइम आ रहा है)
- **ज़मान क्यूआर साइनिंग अभी तक लाइव नहीं है** - वॉलेट क्रेडेंशियल फ़ाइल की आवश्यकता है (सीड-आधारित, केवल टेस्टनेट)
- **IPFS अपलोड लंबित** - फ़ाइल पॉइंटर स्थानीय पथ का उपयोग करते हैं, वास्तविक सामग्री-संबोधित भंडारण आ रहा है
- **केवल विंडोज** - भविष्य के आरसी के लिए मैकओएस इंस्टॉलर की योजना बनाई गई है
